1. SSG - Static Site Generation -> Here the page is built at built-time. This has the fastest performance for loading
        the page at client.
2. ISR - Incremental Static Regeneration -> Here the static page is updated on demand without a full rebuild.
3. SSR - Server Side Rendering -> Here the page is generated on each request. It is suitable for dynamic content.
4. CSR - Client Side Rendering -> Here the blank HTML is loaded first. Then fetches the data and compiles the JS on 
        the client side.
5. PPR - Partial Pre-Rendering -> It mixes the pre-rendered and dynamic content on the page.

 This also reduces the load on the DB as the query jumps to the data set without unwanted iterations through whole data set.

Questions - 

1. Cookies vs. Local Storage vs. Session Storage
    Cookies: Have a 4KB limit, are used for authentication, and are accessible by both the server and client.
    Local Storage: Has a higher size limit, persists indefinitely, and is ideal for storing application state like user settings.
    Session Storage: Data is deleted when the browser tab is closed, making it useful for temporary data like form inputs.

2. Front-end Application Optimizations
    For a new application, consider the following optimizations:
    Polyfilling: Adds modern JavaScript features for older browsers.
    Compression: Reduces the size of the JavaScript bundle to decrease network payload.
    Minification & Uglification: Makes code smaller by removing unnecessary characters.
    Source Maps: Helps with debugging by mapping minified code back to the original source.
    Code Splitting & Tree Shaking: Ensures only essential JavaScript is loaded initially.

3. Optimizing Large Image Assets
    To optimize large images in an application, you can:
    Sizing & Compression: Use the minimum required dimensions and reduce file size.
    Format: Use efficient formats like WebP.
    CDN: Utilize a Content Delivery Network for faster delivery and caching.
    Lazy Loading (Load on scroll of Webpage-): Load images only as the user scrolls.
    srcset Attribute: Serve different image sizes based on the user's device.

4. Managing Code Quality
    In large applications, code quality is managed using:
    Linters: Tools like Prettier and ESLint enforce consistent code style.
    Tests: Unit and E2E tests ensure code functionality.
    Scans: Dependency and accessibility scans check for vulnerabilities and ensure accessibility.
    Performance Monitoring: Tools like Lighthouse track core web vitals.

5. Cross-Site Scripting (XSS) Attacks
    An XSS attack involves an attacker injecting malicious JavaScript code into an application. 
    You can prevent this by sanitizing all user inputs and avoiding the direct rendering of HTML 
    or JavaScript from the backend.

6. How a CDN Works
    A Content Delivery Network (CDN) is a global network of servers that caches website assets. When 
    a user requests an asset, the CDN routes them to the nearest server, reducing latency and speeding 
    up load times.

7. Micro-frontends
    Micro-frontends split a monolithic front-end application into multiple independent applications. 
    This approach is suitable for large organizations with many engineers, as it helps avoid deployment 
    bottlenecks, though it adds significant complexity to the setup.

Critical CSS
    Critical CSS is the minimal set of styles needed to render the content that is visible to the user 
    without scrolling, known as the "above the fold" content [00:15]. The video explains that extracting this CSS,
    often with a webpack plugin using a headless browser, can significantly improve web performance [00:44].

ARIA Attributes
    The video highlights that while it's best practice to use semantic HTML, ARIA (Accessible Rich Internet Applications) 
    attributes should be used for non-semantic elements (like div or span) to improve accessibility when semantic tags
    cannot be used due to design constraints [01:58].

Script Tag Attributes: defer and async defer: 
    This attribute downloads a script in the background and executes it just before the DOMContentLoaded event 
    fires [02:57].

async: 
    This attribute downloads and executes a script as soon as possible without waiting for the HTML to be fully 
    parsed [03:12].
    The primary purpose of both attributes is to prevent scripts from blocking the critical rendering path, thus improving 
    page load performance [03:38].

ES6 Imports
The video differentiates between two types of ES6 imports [04:03]:
Normal Imports: These are static, interpreted at build time, and enable features like tree shaking 
and TypeScript type inference.
Dynamic Imports: These are treated like function calls, enabling lazy loading of components or 
modules based on user actions, which improves initial load time.

Core Web Vitals: CLS
CLS (Cumulative Layout Shift) is a Core Web Vital that measures unexpected layout shifts that happen as a
 page loads [05:23]. To fix a poor CLS score, the video suggests solutions like adding fixed width and height
  attributes to images and optimizing font loading [06:03].

Essential vs. Derived State
The video concludes by explaining the difference between essential and derived state in an application [07:10].
Essential State: This state changes independently, typically from user interactions or data fetching (e.g., items
 added to a shopping cart).
Derived State: This state can be calculated from the essential state (e.g., the total price of items in the cart).

Generic Functions
    A generic function is a way to create type-flexible code without using the any type, allowing a function 
    to work with different data types [00:06].

as const and const
    The as const assertion in TypeScript makes an object and all its nested properties immutable at compile time. 
    In contrast, a standard const only prevents the variable from being reassigned, but its properties can still be modified.

private Access Modifier
    The private access modifier restricts a class variable or method to be accessible only from within that class, 
    helping to enforce the principle of interface segregation [04:34].

Decorators
Decorators are functions that add shared functionality to classes or methods by wrapping them with additional code. 
This pattern promotes composition over inheritance and is common in frameworks like Next.js and Angular [06:05].

type vs. interface
A key difference is that interfaces can be merged at build time, while types must be unique [08:16]. Types are recommended 
for defining domain entities, while interfaces are suitable for auxiliary shapes like component props or function inputs.

Type Guard
A type guard is a function that helps narrow down a union type to a specific subtype, allowing you to perform type-specific 
operations [09:51].

Structural vs. Nominal Typing
TypeScript uses structural typing, where two objects are considered the same type if they have the same properties [11:11]. 
This differs from nominal typing, where types must have the same explicit signature or class to be considered the same.

The video explains the Backend for Frontend (BFF) pattern, a specialized service layer that sits between an
application and its backend services [01:42]. This pattern is designed to solve the challenges that arise when 
a single general-purpose API tries to serve multiple types of clients, such as mobile, web, and IoT devices.

Key Concepts
Single API Challenge: The video explains that using a single API for all clients becomes problematic as different clients 
have unique needs [00:24]. For example, mobile devices need less data, while web apps might require more detailed 
information and different formatting [00:32]. This can also create development bottlenecks [01:17].

BFF Solution: The BFF pattern gives each client its own dedicated backend service [01:42]. This allows the backend 
to be specifically tailored to the client's needs, simplifying front-end development and optimizing for performance 
and security [02:09].

Core Benefits
Optimized Data Delivery: Each BFF can aggregate and format data from various microservices in the most efficient 
way for its specific client [02:29].

Simplified Front-End Development: Front-end teams only need to interact with their dedicated BFF, which handles 
all the complexities of the core backend services [02:44].

Independent Scaling: Each BFF can be updated or scaled independently without affecting other clients [05:03].

Netflix as an Example
The video uses Netflix's architecture as a prime example of the BFF pattern [02:50]. Netflix uses a separate 
backend for each client type (Android, iOS, web, TV) to meet the unique requirements of each platform [02:57].

Implementation Approaches
The video concludes by discussing two ways to implement the BFF pattern [05:10]:

Dedicated BFFs: A separate BFF for each client, which is often preferred when different teams manage the applications [05:17].

Shared BFF: A single BFF for multiple user interfaces, which can simplify development but may become overloaded
 with responsibilities [05:24].

* Front-end Architechture (Re-Check)

    This video provides a detailed overview of various front-end architecture patterns, discussing their benefits,
    drawbacks, and suitable use cases. The speaker begins by defining front-end architecture, highlighting that 
    its purpose is to create flexible, testable, and scalable applications, not just to organize files.

Foundational Patterns

    MVC (Model-View-Controller): A foundational pattern that separates an application into three layers: Model 
    (data), View (UI), and Controller (the bridge between them). The video discusses its workflow and 
    limitations, such as the "fat controller" problem.

Web MVC - > 
    Model (Data Store - Redux, Vuex, Pinia)
    View (UI components - React, Vue Components)
    Controllers (Hooks, composables)  

MVP (Model-View-Presenter): An evolution of MVC where the presenter handles all logic, making the view a 
    passive UI layer to improve testability and structure.

MVVM (Model-View-ViewModel): This pattern introduces the ViewModel layer for UI-related logic and uses
    two-way data binding, making it suitable for applications with complex UI interactions.

Advanced Patterns
    Hierarchical MVC (HMVC): A scalable extension of MVC that breaks a large application into smaller, 
    independent MVC units, ideal for large-scale projects.

    MVVMC (Model-View-ViewModel-Coordinator): Extends MVVM with a "Coordinator" layer to specifically 
    manage navigation and screen transitions.

    Viper (View-Interactor-Presenter-Entity-Router): Primarily for mobile development, this pattern 
    offers a highly structured approach with each component having a single, clear responsibility.

Modern Architectural Styles
    Clean Architecture: Organizes software into concentric layers with dependencies pointing inward, ensuring 
    that core business logic is independent of frameworks, databases, and the UI.

    Hexagonal Architecture: Also known as Ports and Adapters, this pattern uses clear contracts for interactions,
    making it useful for systems with multiple distributed parts.

    Screaming Architecture: Suggests that a codebase's structure should be organized around business domains and 
    features, not technical details.

    Vertical Slices: A feature-based approach where each "slice" is a self-contained feature, containing its own 
    logic, data, and UI components, which enhances modularity and is good for large teams.

Clean Architecture

    | Top - Frameworks and Drivers  |  Database, External Interfaces, UI
    | Interface Adapters            |  Controllers, Presenters, Gateways
    | Application Business Logic    |  Use Cases
    | Base - Core business logic    |  Entities

    - Entities - Represent business logic of domain. They are rarely modified. They can be objects with methods or simply 
    a set of data structurs and functions.
    - Use cases - Define application specific business rules. It controls the flow of data to and from the entities.
    - Interface adapters - Adapt input to use cases and outputs to external interfaces.
    - Frameworks and drivers - Represents the user interface and external dependencies such as database.

    Two principles of Clean Architecture - 
        1. Seperation by diving the software into layers - The entity and external interface layers are mandatory, other 
        layers can be discarded if not needed. Additional layers can also be added if needed.
        2. The dependency rule - The outer layers depends on inner layer and not vice versa. Nothing in inner layers knows about outer layer.

    Local first application -
        Indexed DB, UI
        -> API, UI adapters
        -> Use cases
        -> Store

    Pros -
    1. Highly testable
    2. DB independent - Decoupled
    3. UI independent - Isolated

    Cons - 
    1. Higher barrier of entry
    2. Increased complexity

Hexagonal Architechture

    Core Layer - Business Logic
    Above Layer - Input outputs (Input port, API, Output ports)

    Connected are the Driving side - 
        Team A - UI, console, test script 
        Team B - DB, Message Queue, HTTP

    Features - 
        Distributed development
        Contract Programming - Here the contracts are placed to set clear expectation for interaction 
        between domain core and adapters. We enforce contracts with response validators and integration test.

    Use - 
        Full stack development.
        Multiple interface - When your app interacts with various interfaces (Rest AAPI, Gtraph QL, etc)
        Rich web application - 

    Not to use -
        Simple application
        Small team/ project


    Clean Architecture VS Hexagonal Architechture

        Clean Architechture - 
        1. Seperation into layers - Entity, Use case (Business Logic), Controllers, Infrastructure.
        It is good when the application focus on layer seperation within a single application.

        Hexagonal Architechture -
        1. Seperation between domain logic and infrastructure adapters.
        It is suitable when the system involves multiple distributed parts (Application, services, 
        or interfaces) interacting with central core domain logic.

Seven popular design pattern

This video provides a summary of seven software design patterns, categorized into 
three types: creational, structural, and behavioral. 
These patterns offer reusable solutions to common programming problems.

Creational Patterns
    Creational patterns are focused on object creation.
    
    Singleton Pattern: Ensures that a class has only one instance and provides a single point 
    of access to it. An example is a logging system that uses a single logger for all activities.
    
    Builder Pattern: Used to construct complex objects step-by-step. This is useful when a 
    constructor would otherwise have many optional parameters, allowing for cleaner code and 
    method chaining.

    Factory Pattern: Creates objects without specifying the exact class that will be created. 
    It centralizes object creation logic into a single factory, which makes the code more 
    flexible and maintainable.

Structural Patterns
    Structural patterns deal with how objects relate to each other.

    Facade Pattern: Provides a simplified interface to a complex system of classes. It hides 
    the underlying complexity behind a single, clean interface, like a "buy now" button that 
    initiates multiple complex processes.

    Adapter Pattern: Allows objects with incompatible interfaces to work together. It acts 
    as a translator, similar to a physical adapter that lets a laptop plug into a different 
    type of port.

Behavioral Patterns
    Behavioral patterns handle communication and interaction between objects.

    Strategy Pattern: Allows an algorithm's behavior to be selected at runtime. It defines
     a family of interchangeable algorithms, such as different strategies for getting to 
     work (driving, biking, or taking the bus).

    Observer Pattern: Defines a one-to-many dependency between objects. When one object 
    (the subject) changes state, all of its dependents (the observers) are automatically 
    notified and updated. A YouTube subscription system is a good example of this pattern.
