Observability & Testing
Here's a breakdown of the key concepts for observability and testing in mobile system design.

1. Unit Testing
    Unit testing involves testing individual, isolated components or "units" of your code to ensure they 
    work as expected.
    - iOS: `XCTest` is Apple's native testing framework, integrated directly into Xcode. It's the standard 
    for unit, integration, and performance testing on Apple platforms.
    - Android: `JUnit` is a popular framework for writing and running unit tests. It's a standard tool for 
    Java and Kotlin, and it's widely used in Android development.

2. Mocking Frameworks
    Mocking frameworks create mock objects that simulate the behavior of real objects, which is essential 
    for isolating the component being tested.
    - iOS: Mockingbird is a popular mocking framework for Swift, using a code generation approach.
    - Android: Mockito is the go-to mocking framework for Android. It allows you to create and configure mock 
    objects for testing.

3. Integration Testing
    Integration testing verifies that different modules or services in your app work together correctly. 
    This is done by testing the communication and data flow between them.

4. UI Testing
    UI testing automates user interactions to ensure the app's user interface functions as intended.
    - iOS: `XCUITest` is Apple's framework for UI testing, allowing you to write tests that simulate taps, 
    swipes, and other user actions. **EarlGrey 2.0** is an open-source framework from Google for UI testing 
    on iOS.
    - Android: `Espresso` is Google's primary UI testing framework for Android. It's designed to be fast and 
    reliable. **UI Automator** is a framework that allows you to test apps on a device, even those outside 
    of your own.

5. CI/CD
    CI/CD (Continuous Integration / Continuous Delivery)** is a set of practices that automates the building, 
    testing, and deployment of software. It helps teams ship code faster and with fewer bugs.

6. E2E Testing
    E2E (End-to-End) testing** simulates the full user journey through an application, from start to finish, 
    to ensure the entire system works correctly.
    - Detox and Appium are popular frameworks for cross-platform E2E testing. They allow you to write tests 
    that run on both iOS and Android.

7. Beta Distribution & Rollouts
    This phase involves distributing pre-release versions of the app to a limited audience for testing and feedback.
    - iOS: TestFlight** is Apple's service for distributing beta versions of apps.
    - Android: Google Play Console** provides tools for managing internal, closed, and open beta tests.
    - Phased rollouts** (or staged rollouts) are a strategy for releasing a new app version to a small 
    percentage of users first, and then gradually increasing the percentage over time. This helps to catch 
    major issues before they affect all users.

8. Logging & Monitoring
    Logging involves recording events and information about your app's behavior. **Monitoring** is the process 
    of collecting and analyzing this data to understand the app's health and performance. This data is critical 
    for debugging issues in production.

9. Metrics & Dashboards
    Metrics are quantifiable measures of your app's performance, such as crash-free users, network latency, and 
    app startup time. **Dashboards** are visual representations of these metrics, providing a centralized view of the 
    app's status and health.

10.Crash Reporting
    Crash reporting is the process of capturing and logging fatal errors in your app. Services like "Firebase Crashlytics"
    and "Sentry" automatically collect crash reports, providing valuable data to help developers debug and fix issues.
