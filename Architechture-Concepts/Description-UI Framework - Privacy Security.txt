Privacy & Security
Here are the details for key privacy and security considerations in mobile app development.

---------------------------------------------------------------------------------------------------------

a. Data Encryption
    Data encryption is the process of encoding data so that it cannot be understood by unauthorized parties.
    - In transit: Data should be encrypted using secure protocols like HTTPS (TLS/SSL) when being sent over 
    a network. This prevents man-in-the-middle attacks where an attacker could intercept and read data.
    - At rest: Data stored on the device should be encrypted to protect it from unauthorized access if the 
    device is lost or stolen. This applies to databases, files, and key-value stores.

b. Secure Storage
    Secure storage refers to using specific, OS-provided mechanisms to store sensitive data in an encrypted 
    and protected manner.
    - iOS: Keychain is the recommended way to store sensitive information like passwords, tokens, and cryptographic 
    keys. It is a secure, encrypted database managed by the OS.
    - Android: EncryptedSharedPreferences and the Android Keystore system are used to securely store small pieces 
    of data and cryptographic keys, respectively.

c. Minimize Data Collection
    To enhance user privacy, apps should only collect the data that is absolutely necessary for their functionality. 
    This minimizes the risk of a data breach and builds user trust. When collecting data, developers should be 
    transparent about what is being collected and why.

d. Minimize Permission Usage
    Apps should request only the permissions required to perform their core functions. For example, a weather app 
    shouldn't request access to the user's photos. This follows the principle of least privilege and reduces the 
    pp's attack surface.

e. Data Retention & Deletion
    Developers must establish clear policies for data retention, outlining how long user data will be stored. They 
    must also provide users with a straightforward way to delete their data from the app and associated servers. 
    This is a critical requirement for compliance with many privacy regulations.

f. Code Security, Integrity, Obfuscation
    - Code security involves writing code that is resilient to common vulnerabilities like injection attacks and 
    insecure data handling. This includes using a secure Software Development Lifecycle (SDLC) and conducting 
    code reviews.
    - Code integrity ensures that the code has not been tampered with. Techniques like code signing and checksums 
    verify that the app is genuine and unmodified.
    - Obfuscation is the process of making code difficult for humans to understand. This can help protect 
    intellectual property and make reverse engineering more challenging for potential attackers.

g. Privacy Compliance
    Adherence to privacy regulations is crucial.
    - GDPR (General Data Protection Regulation): This EU regulation provides strict rules on how personal data 
    must be collected, processed, and stored. It includes requirements for user consent, data access rights, 
    and data portability.
    - CCPA (California Consumer Privacy Act): This US law gives California residents more control over their 
    personal data, including the right to know what data is collected and the right to opt out of the sale of 
    their data.
    - App Store & Google Play Policies: Both platforms have strict privacy policies that developers must follow, 
    including requirements for privacy policies, data handling disclosures, and permission usage.
