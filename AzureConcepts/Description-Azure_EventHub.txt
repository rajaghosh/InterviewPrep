

Azure Event Hub - PAAS Event Stream Broker
Direct competition is Apache Kafka API, but far better performance and lower cost.
Fully managed by Azure.
AMQP 1.0 standard complaint while Apache uses wire compatibility
Cross Platform support.
Industry leading reliability and availability
Fast

Diff between Apache Kafka vs Azure Event Hub

User Model - Both same. Partitioned event-stream broker with high-availability replication.
Architechture -
	a. Event Hub 
			- Multi-tenant
			- 3-tier gateway/broker/storage cluster model, with tenant-isolation all tier independently scalable.
	b. Apache kafka 
			- Single-tenant
			- Monolith. Need to increase broker instance in a cluster to scale any dimension.
Cluster Manager 
	a. Event Hub - Azure Service Fabric
	b. Apache Kafka - Apache Zookeeper, Krift


SKU and Pricing - Azure Event Hub
	1. Standard - Shared Resource Model
		a. Blended capacity and consumption based pricing
		b. Upto 40MB/s ingress.
		c. Throughput Units - 1TU = min(1000msg/s , 1MB/s in) / min(2000msg/s , 2MB/s out)
		d. Includes Capture
	2. Premium - Isolated Resource Model
		a. Capacity based pricing model. 
		b. Upto 120MB/s ingress.
		c. Premium Units - 1PU = 5-10MB/s 
		d. Includes Capture
	3. Dedicated - Dedicated Resource Model
		a. Capacity based pricing model.
		b. Full Isolated cluster
		c. Beyond 120MB/s ingress (>4GB/s in Prod)
		d. Capacity Unit - 1CU

Basic concepts (From Producer Side)
	1. Event producers - Send events via AMQP (Advanced Message Queuing Protocol) , HTTP or Apache Kafka
		- Events are sent to event hub. Each event hub is partitioned upto 1 to 32 partition.
		When events are sent from the producers event hub partitions will capture the events unequally mostly. That is if there are 8 partitions 
		and we have 16 events we can have a single partition may hold 5 events and other partitions can have less events. So each partitions will
		grow at different rate.
	2. Partition Key - Each partitions are ordered from oldest to newest like a QUEUE. But the orders are not maintained across partitions.
		 So to process multiple events in order we need a PARTITION KEY. The Parition Key will ensure the events attached to the partition key
		 lands in the same partition.
	3. Namespaces - Generally an event hub will represent an unique stream of data. So if we need to process N unique data stream
		we need N event hubs.
		So a Namespace is a logical collections of event hubs. So under a namespace event hubs will-
			a. Scope containers
			b. Share properties

Basic Concept (From Consumer Side)
	1. Consumer Group - Is a unique view on Event Hub data. So typically each consumer group represents a seperate application.
	2. Consumers - Are processes that read event data (AMQP 1.0). They are part of consumer group.
	3. Offset - Position of the event in a partition.
	4. CheckPointing - Is process of saving Offset on Client Side.

To receive event from .net project
	We will be using a .net code.
	We will read the events and store it to a blob storage. The container we use will have check points.
	Code -

		private const string connectionString = "<event_hub_connection_string>"; //We have to create a SAS token with listen claim then generate the connection string
        private const string eventHubName = "<event_hub_name>";
        private const string blobStorageConnectionString = "<blob_connection_string>";
        private const string blobContainerName = "<container_name>";
        
		static async Task Main()
        {
            string consumerGroup = EventHubConsumerClient.DefaultConsumerGroupName;

            // Create a blob container client that the event processor will use 
            BlobContainerClient storageClient = new BlobContainerClient(blobStorageConnectionString, blobContainerName);

            // Create an event processor client to process events in the event hub
            EventProcessorClient processor = new EventProcessorClient(storageClient, consumerGroup, connectionString, eventHubName);

            // Register handlers for processing events and handling errors
            processor.ProcessEventAsync += ProcessEventHandler;
            processor.ProcessErrorAsync += ProcessErrorHandler;

            // Start the processing
            await processor.StartProcessingAsync();

            // Wait for 10 seconds for the events to be processed
            await Task.Delay(TimeSpan.FromSeconds(10));

            // Stop the processing
            await processor.StopProcessingAsync();
        }
        static async Task ProcessEventHandler(ProcessEventArgs eventArgs)
        {
            // Write the body of the event to the console window
            Console.WriteLine("\tRecevied event: {0}", Encoding.UTF8.GetString(eventArgs.Data.Body.ToArray()));

            // Update checkpoint in the blob storage so that the app receives only new events the next time it's run
            await eventArgs.UpdateCheckpointAsync(eventArgs.CancellationToken);
        }

        static Task ProcessErrorHandler(ProcessErrorEventArgs eventArgs)
        {
            // Write details about the error to the console window
            Console.WriteLine($"\tPartition '{ eventArgs.PartitionId}': an unhandled exception was encountered. This was not expected to happen.");
            Console.WriteLine(eventArgs.Exception.Message);
            return Task.CompletedTask;
        }
